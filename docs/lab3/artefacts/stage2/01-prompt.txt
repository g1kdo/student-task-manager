PROMPT SHAPE — why it is built this way

The #file: references are the whole point of using an IDE UX at this stage.
Copilot reads the real Task.java and TaskManager.java, so the draft is grounded
against the code as it actually is rather than as Stage 1 imagined it — that is
what closes the TODO markers.

"Do not invent classes or introduce new dependencies" and the explicit list of
things to reuse exist because the failure mode of an IDE agent on an existing
codebase is a parallel implementation that compiles but duplicates what is
already there.

"Keep the existing boolean addTask(String) behaving exactly as it does now" is
a regression fence: 69 tests depend on it, and naming that constraint is
cheaper than discovering it from a red build.

"Show me the diff before applying" is the single human approval gate for this
stage. It is what keeps the workflow one-decision-per-stage rather than
one-decision-per-file.
